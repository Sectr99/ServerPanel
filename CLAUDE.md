# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Arduino/PlatformIO firmware for the Waveshare ESP32-P4-WIFI6-Touch-LCD-7B (7" 1024x600 MIPI-DSI, GT911 touch, Wi-Fi via an onboard ESP32-C6): a multi-function homelab panel (server stats for a PC and an Unraid NAS, Bambu printer with camera, weather radar, Spotify controller, macro pad, Stream Deck, launcher). docs/SETUP.md covers the server-side setup; README.md is the GitHub overview. The desk enclosure (a Fusion script that writes STLs) is in `cad/`, see [cad/README.md](cad/README.md).

**Start here:** [docs/STATUS.md](docs/STATUS.md) (panels, what's done, open investigation, user decisions) and [docs/DESIGN.md](docs/DESIGN.md) (goals, screens, look, data sources, architecture, how to extend). Update STATUS.md at the end of a session.

## Commands

pio lives at `$USERPROFILE/.platformio/penv/Scripts/pio.exe`. Always prefix with `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`: when output is piped, esptool's progress bar crashes under cp1252 and the upload hangs forever.

- Build: `pio run -e p4`
- Flash over Wi-Fi (default): `pio run -e p4-ota -t upload [--upload-port <ip>]` (default IP/password in `platformio.ini [ota]`; `.local` names don't resolve on this network). Its DEBUG output prints the password (`auth=...`): always filter it, e.g. `| grep -E "Result|SUCCESS|FAILED|No response"`.
- Flash over USB: `pio run -e p4 -t upload --upload-port COMx` (the CH343 UART port; look it up with `pio device list`, another ESP32 may be plugged in). Required when `partitions.csv` changes or the panel can't take OTA.
- Use the project `flash` skill (`.claude/skills/flash/SKILL.md`) for the full flash/boot-log procedure.
- Serial log: `"$USERPROFILE/.platformio/penv/Scripts/python.exe" tools/serial_log.py [--seconds N] [--reset] [--no-touch]` (finds the CH343 port; doesn't reboot unless `--reset`). Run long captures in the background. Crashes also leave a core dump (see Hardware quirks).
- PC preview (no tests exist; this is the visual check): `ZIG="$LOCALAPPDATA/Microsoft/WinGet/Packages/zig.zig_Microsoft.Winget.Source_8wekyb3d8bbwe/zig-x86_64-windows-0.17.0/zig.exe" sh tools/build-preview.sh /c/tools/SDL2/SDL2-2.32.10/x86_64-w64-mingw32 [samples]`. Sample camera/radar data: `python tools/preview_data.py` (into `.pio/preview/`, not in the repo) renders every page/detail view/settings/launcher/app screen to `preview*.png` in the repo root using the real `src/ui.cpp`. Needs a firmware build first (uses LovyanGFX from `.pio/libdeps/p4`). Screens are listed in `tools/preview.cpp`. Add `samples` as a second argument to render every screen in five data scenarios (normal, hot, idle, offline, night) to `samples/<scenario>/`.
- microSD files over Wi-Fi: `python tools/sd_upload.py <ip> [folder]` copies a folder (default `sd/`, from `mkfonts.py sd`) to the card's root, skips files already there at the same size, then reboots the panel. Password from `ota.ini`.
- Fonts: `python tools/mkfonts.py [family]` turns `tools/fonts/*.ttf` into `src/fonts/<family>.h` (VLW byte arrays, one per UI role); select with `FONT_HEADER` in `config.h`. `python tools/mkfonts.py icons` writes `src/fonts/icons.h`: Material Symbols Rounded icons as VLW fonts (`I_S`/`I_M`/`I_L` in ui.cpp) plus `ICON_<NAME>` strings; the icon list is `ICONS` in mkfonts.py, and the 15 MB source font downloads on first use (git-ignored).

Don't build while the user is building from VS Code: concurrent builds clobber `managed_components`. Keep the project in a path without spaces (ESP-IDF rejects them). Full rebuilds take ~8 minutes; run them in the background.

## Architecture

Source files, split so the UI builds on a PC:

- `src/main.cpp`: everything hardware/network. A fetch task on core 0 polls the sources into a `Data` struct guarded by a spinlock (`shared`/`mux`); `loop()` copies it, polls touch every 20 ms, redraws once a second, handles OTA, sleep/backlight/night mode, NVS settings persistence, and sends macro keys over TinyUSB HID. Also panel init (EK79007 DSI, double-buffered: the sprite draws straight into the back frame buffer, `present()` flips) and GT911 gesture detection.
- `src/ui.cpp` / `src/ui.h`: all drawing and navigation, with **no Arduino/ESP dependencies** (keep it that way, or the preview breaks). main.cpp drives it through the `ui*` functions in ui.h (`uiSample`, `uiDraw`, `uiTap`, `uiSwipe`, `uiTake*` one-shot flags). Drawn elements register tap rects during draw; `uiTap` hit-tests them. Owns pages, detail views, settings page, launcher and app screens.
- `src/companion.cpp`: the Stream Deck Function's Bitfocus Companion Satellite client (TCP, line protocol) in its own task. Key images pass to loop() through per-key slots under a mutex and are decoded by `uiDeckKey` in ui.cpp; taps go back through a queue so only that task touches the socket.
- `src/printer.cpp`: the Bambu printer page's MQTT client (TLS 8883, user `bblp`, LAN access code) in its own task. It merges the printer's partial reports into a `Printer` struct that `loop()` copies into `Data.pr` after taking `shared`. It must stay out of `shared`, because the fetch task writes all of `shared` back after each multi-second round. A second task streams the camera (TLS 6000, 1280x720 JPEG about 1/s) only while `uiCamWanted()`; `printerCamPump()` hands frames to `uiCamFrame`, and ui.cpp decodes each one once into a cached sprite. The preview uses a real frame from `.pio/preview/camera.jpg` if present (not in the repo).
- `src/radar.cpp`: the weather radar app's downloads in its own task, only while `uiRadarWanted()`: Esri dark gray map tiles (base JPEG + label PNG layers) and NOAA MRMS radar frames (WMS `GetMap` in EPSG:3857, sized to the map so it lines up with the tiles), both HTTPS over one shared TLS connection; ZIP lookups over plain HTTP. The base and label layers are built once per place and zoom (`uiRadarLayer`); a loop frame only copies the base, draws the radar PNG and lays the labels over it (`uiRadarCompose`). Decoding the label tiles per frame instead kept core 0 busy long enough to trip the task watchdog. The image work (layers, compose, the Web Mercator maths) lives in ui.cpp so the preview runs it, from tiles saved in `.pio/preview/radar/` (not in the repo).
- `src/spotify.cpp`: the Spotify app's Web API client in its own task, created when the app opens and deleted 30 s after it closes (its stack only exists while used). One TLS connection shared by `api.spotify.com` and the hourly token refresh at `accounts.spotify.com`; album art over plain HTTP from `i.scdn.co`, decoded in the task by `uiSpotifyDecode`. Controls (`uiTakeSpotify` -> `spotifyCommand`) apply to its state at once and are sent from the task; `spotifyPump()` hands state over, advancing the progress once a second. `tools/spotify_auth.py` gets the refresh token into config.h. The Web API changed in 2026: Liked Songs is `/me/library` with URIs (the `/me/tracks` routes are gone), and a dev-mode app's owner needs Premium.
- `src/config.h`: Wi-Fi, IPs, sensor IDs, Unraid API key, printer IP/serial/access code, macro key list, and first-boot defaults for settings (including the radar location). Contains secrets: never echo them. Git-ignored, like `ota.ini` (the `[ota]` IP and password that `platformio.ini` loads via `extra_configs`); the committed templates are `src/config.example.h` and `ota.example.ini`. A new config define needs adding to the template too, with any secret value blank.

Key conventions:
- `Settings` (ui.h) is saved as one NVS blob loaded by length: **only append fields at the end**; bump `version` only for incompatible changes. `config.h` values are first-boot defaults; after that the saved settings win.
- History: `HIST_N = 360` points per graph window regardless of 15/30/60 min; changing the window clears history.
- `Page` (ui.h) is saved by number as `startPage`: only append. A new page also needs its `startL` label in settings, and shifts the header gear 22 px left (update the gear tap in `tools/preview.cpp`).
- Function (settings): each panel boots/wakes into Server Stats, Macro Pad, Launcher, Stream Deck, Weather Radar or Spotify via `uiHome()`. The `Function` enum is saved by number (append only), and every value but `FN_LAUNCHER` doubles as a launcher app id. New launcher apps go in `apps[]` in `drawLauncher` (two wide tiles over three: full now) and dispatch on the `ACT_APP` arg.
- Palette (`BASE[]` in ui.cpp) is scaled by `THEME_DAY`/`THEME_NIGHT`; status colors (amber/red) are deliberately distinct from series colors. Color thresholds are the `sev(value, warn, crit, color)` calls.
- Partitions (`partitions.csv`): two 6 MB OTA slots + LittleFS (unused so far). Flash is 32 MB but only 16 MB is used (more needs 4-byte addressing).

## Hardware quirks

- Touch panel is mounted 180° from the display (`TOUCH_FLIP_X/Y = 1`). The GT911 drops out mid-press, so a gesture only ends after 80 ms without touch.
- `WiFi.persistent(false)`: flash writes stall the PSRAM cache and glitch the display. Same reason settings saves are debounced 3 s.
- Internal RAM budget: the framework build allocates mbedTLS in internal RAM (~35 KB per TLS connection, ~30 KB more during a handshake), so `setup()` swaps its allocator to PSRAM first (`mbedtls_platform_set_calloc_free`, `tlsCalloc` in main.cpp); a TLS connection now costs internal RAM only for its socket. Received packets still queue in internal RAM (64 KB TCP window), so big downloads by an idle-priority task can dip it: Spotify fetches album art in 16 KB Range pieces for this. Before the swap: Printer MQTT is open except while the radar app is on screen (`printerPause`); the camera, the radar and Spotify take turns (main.cpp stops the others before one connects). Three at once ran internal RAM out and wedged the link to the ESP32-C6 (`rpc_core: Response not received`, every request `HTTP -1`) until a reboot. For the same reason, create ArduinoJson documents as `JsonDocument doc(&psram)` (`psram_json.h`): malloc puts blocks under 4 KB in internal RAM, and a parsed document is many small blocks. The log's "RAM free X KB, lowest Y KB" lines track it.
- Task watchdog (5 s, watches IDLE0): HTTPClient's reads (`Stream::timedRead`) and PubSubClient busy-wait for slow data without letting the idle task run. Any network task above idle priority on core 0 needs timeouts under 5 s, and long CPU work (image decoding) must not run back to back: the radar and camera tasks run at `tskIDLE_PRIORITY` for this reason (the camera also skips stale frames after a Wi-Fi hiccup). Crashes leave a core dump in the `coredump` partition: read 0xFF0000 (64 KB) with esptool and decode with `python -m esp_coredump info_corefile --core <file> --core-format raw --gdb <riscv32-esp-elf-gdb> .pio/build/p4/firmware.elf`. Every build embeds its compile time, so a rebuild never matches a panel's dump SHA even with identical source: then cut the ELF core out of the dump (it starts at the `\x7fELF` signature, 24 bytes in; the length is the first 4 bytes), run `riscv32-esp-elf-gdb-no-python.exe -batch -ex "thread apply all bt" firmware.elf core.elf`, and read the panic reason from the core's `ESP_PANIC_DETAILS` note.
- DSI `phy_clk_src` must be 0 or it aborts. Backlight is GPIO32 PWM, inverted.
- microSD (slot 0) shares the SD host with the C6's Wi-Fi link (slot 1). The card runs at 40 MHz like the Wi-Fi slot: at 20 MHz the driver's per-slot clock switching timed the card out under traffic. Don't write to the card while big Wi-Fi transfers stream in: on panel B's slower card that wedged the C6 link (`rpc_core: Response not received`) until a reboot; `sd_upload.py` sends 1 MB pieces that the panel writes between transfers.
- The C6's esp_hosted version RPC fails at boot; harmless.
- The `-I$PROJECT_PACKAGES_DIR/.../libraries/FS/src` build flag is needed because the USB library's MSC files include FS.h (`${platformio.packages_dir}` mangles Windows backslashes; `lib_ldf_mode` deep+ breaks Wi-Fi).
